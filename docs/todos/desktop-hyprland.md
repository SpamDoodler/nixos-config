## 2. Hyprland vs the alternatives (answer)

First, a correction: **Hyprland's native configuration is hyprlang, not Lua.**
This repo opts into `configType = "lua"`, which is the source of the Lua files.
If the main complaint is Lua, the cheapest fix is to use the native hyprlang
config (`hyprland_hy3.nix` already demonstrates it), not to change compositors.

Options as of late 2026:

| Compositor | Language | Config | Model | Strengths | Costs |
|---|---|---|---|---|---|
| **Hyprland** | C++ | hyprlang (or this repo's Lua mode) | Dynamic tiling | Most features, plugins, animations, active | Fast churn, plugin ABI breakage, C++ |
| **Niri** | Rust | KDL | Scrollable columns | Clean codebase, stable daily use, live reload, no window resizing surprises | Different workflow, smaller ecosystem, scrollable model |
| **Sway** | C | i3-style text | Manual tiling | Rock-solid, i3-compatible, your fallback | Minimal effects, slower feature development |
| **River** | Zig | External program/shell | Tag-based dynamic | Minimal, scriptable, clean | Small ecosystem, more DIY |
| **Wayfire** | C++ | INI | Dynamic/plugins | Effects and plugins | Less active than Hyprland/Niri |

Recommendation:

- **Stay on Hyprland for now.** It has the features and plugin ecosystem you
  actually use (hy3, Waybar, hyprpaper, portals, screenshots).
- If you want to reduce config pain, switch the active module to native
  hyprlang first. That is a small, reversible change.
- If you want the cleanest modern Rust codebase, **Niri** is the strongest
  candidate. It is stable for daily use and has a clean KDL config, but the
  scrollable-column workflow is a real change. Test it in a TTY with
  `niri-session` and a minimal config before migrating.
- Sway remains the low-drama fallback; do not remove it.

Do not migrate just because a project is written in Rust. Migrate if the
workflow is better. A compositor trial should be a separate project with its
own branch and a way back.

### If you trial Niri

- Add `pkgs.niri` and a minimal `~/.config/niri/config.kdl`.
- Start with `niri-session` from a TTY; keep Hyprland installed.
- Test: HDMI, fcitx5, portals/screen sharing, screenshots, lock/idle, Waybar,
  Steam/XWayland, suspend/resume, and your hy3-style keybindings.
- Niri uses its own IPC (`niri msg`), not `hyprctl`; wallpaper/waybar scripts
  need a compositor abstraction or a Niri-specific path.
- Do not delete the Hyprland config until Niri has survived a week.

## 3. hy3 and a better plugin strategy (P2)

hy3 provides i3-like manual tiling, tabs, and groups. It is the reason the
fallback exists: plugin ABI changes can break the session.

Alternatives to evaluate:

1. **Native Hyprland groups/tabs + master/dwindle layout.** Hyprland has
   built-in window groups and tabbed display; this removes a third-party plugin
   from the critical path. Test whether it covers your hy3 workflow.
2. **Hyprland's built-in scrolling layout** (if available in your version) for
   a Niri-like workflow without switching compositors.
3. **hy3** keep as-is, but pin the Hyprland/plugin versions together and keep
   the fallback. This is the status quo and is acceptable.
4. **hyprscrolling / hyprsplit** — smaller plugins; assess maintenance and ABI
   risk before adding.

Recommended path: try native groups + master for a week in a separate config;
if it covers 90% of your hy3 usage, drop hy3 and the fallback complexity. If
not, keep hy3 and the fallback.

### Target

- Save to `~/Pictures/Screenshots/` (create it in the config, not manually).
- Filename: `%Y-%m-%d_%H-%M-%S.png`.
- Full screen: `Print`.
- Region: `SUPER + SHIFT + S` → `slurp` → `grim` → `wl-copy` (and optionally
  `satty`).
- Window: `SUPER + CTRL + S` → `hyprctl activewindow -j` geometry → `grim`.
- Notification on success with `notify-send` (requires mako/swaync).

Sketch:

```sh
mkdir -p "$HOME/Pictures/Screenshots"
file="$HOME/Pictures/Screenshots/$(date +%Y-%m-%d_%H-%M-%S).png"

# Region
grim -g "$(slurp)" "$file" && wl-copy < "$file"

# Window
geom="$(hyprctl activewindow -j | jq -r '"\(.at[0]),\(.at[1]) \(.size[0])x\(.size[1])"')"
grim -g "$geom" "$file" && wl-copy < "$file"

# Full screen
grim "$file" && wl-copy < "$file"
```

Use `wl-copy < "$file"` (not `wl-copy "$file"`, which copies the path).

### How satty works (answer)

Satty is a Wayland screenshot annotation tool. It opens an image, lets you draw
arrows/boxes/text/blur, then saves or copies the result. It is not a screenshot
tool itself; it consumes `grim` output.

Pipeline:

```sh
grim -g "$(slurp)" - \
  | satty --filename - \
      --output-filename "$HOME/Pictures/Screenshots/$(date +%Y-%m-%d_%H-%M-%S).png" \
      --copy-command wl-copy
```

`--filename -` reads stdin, `--output-filename` writes the annotated image, and
`--copy-command wl-copy` puts it on the clipboard. Verify the exact flags with
`satty --help` on the installed version. If you prefer a simpler tool, `swappy`
is the alternative; satty is Rust and more actively developed.


Add them to `modules-right` (or a new group). `amdgpu_bl1` is the current

Fix the temperature module: `thermal-zone = 0` is not reliable on AMD. Use the
k10temp hwmon path:

```jsonc
"temperature": {
  "hwmon-path": "/sys/class/hwmon/hwmon2/temp1_input",
  "critical-threshold": 85,
  "format": "{temperatureC}°C"
}
```

Verify the path with `sensors` and `ls /sys/class/hwmon/*/name`; hwmon indices
can change between kernels. Consider `hwmon-path` for `amdgpu` if you want GPU
temperature instead.

### Clock seconds (answer)

Keeping `interval = 1` costs one wakeup per second. On this hardware it is
typically well under 1% CPU and a small fraction of a watt, but it does prevent
the deepest idle states. Since Waybar already polls CPU/memory every 5 seconds,
the marginal cost is small. Keep seconds. If battery life becomes a priority,
measure with `powertop` and consider `interval = 60` + `{:%H:%M}` as an
experiment.

### Other Waybar fixes

- `battery` should have warning/critical states and a tooltip.
- `network` should show the SSID and signal, and a disconnected state.
- `pulseaudio` can use `pwvucontrol`/`pavucontrol` on click; `pavucontrol` is
  already installed.
- Add `hyprland/window` only if you want a title; it can be noisy.
- `waybar` is currently started by the Hyprland `exec` block, not a systemd
  service. `programs.waybar.systemd.enable = true` gives restart-on-crash.
  Test it before relying on it.

## 9. UWSM (answer)

UWSM (Universal Wayland Session Manager) wraps a compositor in a systemd user
session. It provides:

- a proper `wayland-session.target` and service ordering;
- clean environment/DBus activation for apps;
- `uwsm app -- <command>` to launch apps in the session;
- graceful shutdown of the compositor and its services;
- better integration with portals, keyring, and user services.

It does **not** replace a display manager, and it is not required for your
TTY1 + `start-hyprland` workflow. Costs: it changes the startup path and can
break assumptions in existing `exec-once`/systemd units. Since Sway must remain
a fallback, keep the current path until you have time to test UWSM separately.

If you adopt it later: `programs.hyprland.withUWSM = true`, start with
`uwsm start hyprland-uwsm.desktop`, and test Hyprland, Sway, portals, and
lock/idle. Do not enable it and change the compositor in the same rebuild.

## 10. Desktop plumbing (answer)

These are separate small services; missing ones cause confusing failures.

| Piece | Examples | What it does | Symptom if missing |
|---|---|---|---|
| Notification daemon | mako, dunst, swaync | Draws `notify-send` notifications | Notifications silently vanish |
| Lock screen | hyprlock, swaylock | Locks the session | No way to lock; screen stays open |
| Idle daemon | hypridle, swayidle | Runs commands after idle/sleep | No DPMS off, no auto-lock |
| Polkit agent | hyprpolkitagent, polkit-gnome | GUI auth prompts for privileged actions | “Authentication required” loops/fails |
| Clipboard manager | cliphist + wl-clip-persist | History and persistence of clipboard | Clipboard empties when app closes |
| Keyring | gnome-keyring, kwallet | Stores app secrets; unlocks at login | Chrome/Git/SSH prompts repeatedly |
| Portals | xdg-desktop-portal-hyprland, -gtk | Screenshot/screencast/file chooser DBus APIs | Screen sharing/file picker broken |
| GVFS/udisks2 | gvfs, udisks2 | Mounts drives, trash, network locations | File manager cannot mount USB |
| xdg-utils | xdg-open | Opens URLs/files with the default app | `xdg-open` does nothing |
| Status bar | Waybar | Workspaces, clock, battery, tray | No panel |
| Wallpaper | hyprpaper, awww, swaybg | Draws the background | Black background |
| Launcher | wofi, fuzzel, walker | App launcher | `SUPER + D` does nothing |

Recommended minimal stack: mako (or swaync), hyprlock + hypridle,
hyprpolkitagent, cliphist (with wipe-on-lock), gnome-keyring, the Hyprland and
GTK portals, udisks2/gvfs, and Waybar under systemd. Add Sway equivalents only
when testing Sway.

## 11. Reliability and maintenance

- Run `hyprctl configerrors` after config changes; it reports parse errors that
  do not always stop the session.
- Keep `hyprland_hy3.nix` as a known-good fallback and test it after Hyprland
  upgrades.
- Pin `pkgs.hyprland` and `pkgs.hyprlandPlugins.hy3` to the same nixpkgs; plugin
  ABI mismatches are the usual breakage.
- Do not delete the old generation before a new Hyprland session has started
  successfully.
- Add `systemd` user units for Waybar, hyprpaper, and notifications so crashes
  restart them; `exec-once` is not supervised.
- Keep `fcitx5 -d` in the startup block, but also enable the fcitx5 systemd
  user service if available; test the input method in GTK/Qt/Electron apps.
- For screen sharing, verify
  `systemctl --user status xdg-desktop-portal-hyprland` and test in Firefox and
  Chrome.
- Document keybindings and the fallback switch in `README.md`.
