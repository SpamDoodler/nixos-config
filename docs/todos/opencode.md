# OpenCode

Priority: **P0/P1**. OpenCode is the most powerful agent on the machine and the
one most likely to touch secrets. The current permission model is useful but is
not a sandbox.

## Original audit snapshot (historical)

The version, credential-file mode and provider observations below describe the
original audit, not a fresh inventory. Current source additions are recorded in
the dated progress section and Graphify section below. Do not infer live secrets
or effective merged provider settings from this snapshot.

- `home/opencode/opencode.nix` is the active Home Manager module.
- `home/opencode/opencode_old.nix` is dead code (~319 lines).
- OpenCode version is 2.2.1; the module asserts `>=2.1.1 <3.0.0`.
- `opencode.jsonc` is generated by Home Manager into the Nix store. It contains
  no secrets and includes agents, commands, permissions, and formatters.
- `~/.config/opencode/opencode.json` is a real local file, mode `0644`, and
  currently contains the Aliyun key. It overrides/merges with the HM config.
- `~/.local/share/opencode/auth.json` is mode `0600`; this is the right place
  for credentials.
- The custom launcher creates a private `.opencode-tmp` per workspace and sets
  `TMPDIR`; this is good hygiene.
- `share = "disabled"`, `update = "disable"`, `plugins = []`.
- Default permissions: read/edit allow `*`; deny `.env`, `*credential*`,
  `*secret*`; webfetch allow `*`; shell ask `*`, then allow a list including
  `python`, `pytest`, `nix eval`, `alejandra --check`; deny `rm`, `sudo`,
  `git push`, `git reset --hard`, `git clean`.
- Subagents `explore` and `review` are read-only; `general`/`scout` disabled.
- The model is `gpt-6-luna` under the `openai` provider. Verify that this is a
  real configured model; it looks like a placeholder.

## Decisions

- Keep the ability to grant broad permissions for overnight runs.
- Do not rely on permissions as a security boundary. Add OS-level sandboxing.
- Use Landlock where practical, plus bubblewrap/systemd hardening.
- Only OpenCode needs the DeepSeek key. Do not export it globally.
- Keep `--auto` as the explicit "overnight" switch, but only inside a sandbox.

## 1. Secrets and auth (P0)

Follow [`security.md`](security.md). OpenCode-specific points:

- Prefer `opencode auth login` → `~/.local/share/opencode/auth.json` (0600).
- Never put keys in `opencode.jsonc`; it is a `/nix/store` symlink.
- A 0600 local `opencode.json` is acceptable for non-secret overrides or a
  `{file:~/.secrets/...}` reference. Delete inline key literals.
- The global `DEEPSEEK_API_KEY` export in `home/shell.nix:22` must go. If a
  tool needs it, wrap that tool and read the key from a 0600 file at exec time.
- Add `.opencode-tmp` to backups' excludes; it may contain prompts and output.
- Rotate keys after any run that had network access and broad filesystem read.

## 2. Permission model (P1)

### Problems

1. **Read is effectively unrestricted.** Denying `.env`, `*credential*`, and
   `*secret*` misses `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config/gh`,
   `~/.config/opencode`, `~/.local/share/opencode/auth.json`, browser profiles,
   `~/.password-store`, `~/.deepseek_key`, `/etc/ssh`, `/etc/shadow`.
2. **Webfetch is fully allowed.** Any fetched page can contain a prompt
   injection that asks the agent to read and POST local data. With `--auto`,
   `ask` is auto-approved, so webfetch must be denied or domain-restricted for
   overnight runs.
3. **Shell prefix allowlists are bypassable.** A pattern such as `git status*`
   can match a command with a shell separator. `python`/`pytest` can execute
   arbitrary code. The allowlist is convenience, not confinement.
4. **The shell deny list is incomplete.** It lacks `curl`, `wget`, `ssh`,
   `scp`, `rsync`, `nc`, `chmod`, `chown`, `mount`, `systemctl`,
   `nixos-rebuild`, `home-manager`, `docker`, `podman`, `kill`, `pkill`,
   `shutdown`, `reboot`, and package managers.
5. **`--auto` approves every non-denied permission,** including edits, shell,
   webfetch, and external directories. The deny list must therefore be the
   security boundary — and it is not sufficient without a sandbox.

### Minimum permission changes

Add explicit denies for secrets and control paths:

```nix
++ rules "read" "deny" [
  "**/.ssh/**" "**/.gnupg/**" "**/.aws/**" "**/.config/gh/**"
  "**/.config/opencode/**" "**/.local/share/opencode/**"
  "**/.password-store/**" "**/.deepseek_key"
  "**/.mozilla/**" "**/.config/google-chrome/**"
  "**/*.pem" "**/*.key" "**/id_*"
  "/etc/shadow" "/etc/ssh/**"
]
++ rules "webfetch" "ask" ["*"]   # or deny for overnight
++ rules "shell" "deny" [
  "curl *" "wget *" "ssh *" "scp *" "rsync *" "nc *"
  "chmod *" "chown *" "mount *" "systemctl *"
  "nixos-rebuild *" "home-manager *" "docker *" "podman *"
  "kill *" "pkill *" "shutdown *" "reboot *"
  "nix profile *" "nix-env *"
]
```

Keep `python`/`pytest` at `ask` unless running inside the sandbox. If you need
them for trusted local tests, use a separate `test` agent with those allows and
no network.

Do not add broad `read` allows for `$HOME`; read only the workspace and
explicitly needed paths.

### Per-agent design

- `build` — normal interactive work, shell ask.
- `explore` — read-only; already correct.
- `review` — read-only; already correct.
- `overnight` (new) — edits and shell allowed, network denied, no secrets, used
  only inside the sandbox. Do not make it the default.
- `test` (optional) — allows `python`/`pytest` but denies network and secrets.

`--auto` can remain the explicit switch, but the safe pattern is:

```sh
opencode-sandbox --auto --prompt "..."
```

where `opencode-sandbox` mounts only the worktree, a private HOME, and the auth
file.

## 3. Sandboxing (P1)

Permissions are advisory. Add layers:

### Layer A: dedicated worktree + clean environment

- Use `git worktree add ../repo-agent -b agent/YYYY-MM-DD`; never run overnight
  on `main`.
- Run as a separate Unix user (`opencode-runner`) with no access to
  `/home/spamdoodler`, SSH keys, browser profiles, or the NixOS repo.
- Give the runner write access only to the worktree and a private tmp/home.
- Review the diff before merging; never auto-push.

### Layer B: bubblewrap

`bubblewrap` (bwrap) gives mount/pid/user namespace isolation without root.
Sketch (verify paths and flags on this system):

```sh
bwrap \
  --unshare-all --share-net \
  --die-with-parent --new-session \
  --clearenv \
  --setenv HOME /tmp/agent-home \
  --setenv PATH /run/current-system/sw/bin \
  --ro-bind /nix/store /nix/store \
  --ro-bind /run/current-system /run/current-system \
  --ro-bind /etc/resolv.conf /etc/resolv.conf \
  --ro-bind /etc/ssl /etc/ssl \
  --bind "$WORKTREE" "$WORKTREE" \
  --tmpfs /tmp \
  --proc /proc --dev /dev \
  --ro-bind "$HOME/.local/share/opencode/auth.json" /tmp/agent-home/.local/share/opencode/auth.json \
  opencode --auto
```

Notes:

- `--share-net` is needed for the API. For no-network runs, drop it; the agent
  cannot call the model, so that is only useful for local-only tasks.
- Do not bind the real `$HOME`, `~/.ssh`, `~/.config`, or the NixOS repo.
- `--ro-bind /nix/store` is needed for the binary and tools; it also exposes
  the world-readable store, which contains no secrets.
- Bind only the auth file, mode 0600, and a private HOME. Better: use a
  provider key scoped to the sandbox and rotate it.
- Test with `bwrap ... sh -c 'ls ~; ls /home/spamdoodler'`; the second must fail.

### Layer C: systemd-run hardening

For resource limits and additional restrictions:

```sh
systemd-run --user --scope \
  -p NoNewPrivileges=yes \
  -p PrivateTmp=yes \
  -p ProtectHome=read-only \
  -p ProtectSystem=strict \
  -p ReadWritePaths="$WORKTREE" \
  -p MemoryMax=8G \
  -p CPUQuota=400% \
  -p TasksMax=512 \
  -p RestrictSUIDSGID=yes \
  -p LockPersonality=yes \
  -p RestrictAddressFamilies='AF_UNIX AF_INET AF_INET6' \
  opencode --auto
```

Some properties may need a system service or cgroup delegation; test each.
`ProtectHome=read-only` plus `ReadWritePaths` is a good default; `PrivateTmp`
prevents access to other tmp state.

### Layer D: Landlock

The kernel already has `lsm=landlock,yama,bpf` in `/proc/cmdline`. Landlock is
an unprivileged, stackable filesystem/network restriction. It is a good fit for
a wrapper around OpenCode:

- restrict reads to the worktree, `/nix/store`, `/run/current-system`, and the
  auth file;
- restrict writes to the worktree and private tmp;
- restrict TCP connect to the API endpoints (Landlock network ABI; verify
  kernel support on `linux_testing` 7.3);
- deny access to `$HOME`, SSH, browser profiles, and the NixOS repo.

Tooling: check whether `landlock-restrict`/`landrun` is packaged in the pinned
nixpkgs. If not, write a small Rust wrapper using the `landlock` crate, or use
bwrap first and add Landlock later. Do not claim Landlock is active until
`/proc/self/attr/landlock` or the tool's own status confirms it.

### Layer E: network egress

For overnight runs, the largest exfiltration risk is network access. Options:

- deny `webfetch` and all shell network tools; allow only the model API;
- run with `--unshare-net` and a Unix-socket proxy that forwards only to the
  provider API;
- use a firewall/network namespace with an allowlist of provider IPs (fragile;
  APIs use CDNs);
- run the model call through a local proxy that logs requests and blocks
  non-API destinations.

At minimum, deny `curl`, `wget`, `ssh`, `scp`, `rsync`, `nc`, and `webfetch`
for overnight; the agent can still edit and run tests locally.

## 4. Overnight run checklist

- [ ] Create a dedicated worktree/branch.
- [ ] Run as a separate Unix user or inside bwrap.
- [ ] Mount only the worktree, auth file, `/nix/store`, and private tmp/home.
- [ ] No SSH keys, browser profiles, `~/.config`, NixOS repo, or password store.
- [ ] Deny network tools and webfetch, or restrict to the API proxy.
- [ ] Set a wall-clock limit (`timeout 8h`) and resource limits.
- [ ] Log stdout/stderr to a file outside the sandbox.
- [ ] On completion: inspect `git diff`, run tests, review before merge.
- [ ] Never `git push`, `nixos-rebuild`, or `home-manager switch` from the run.
- [ ] Rotate the provider key if the sandbox was compromised or misconfigured.

## 6. Verification

```sh
opencode --version
opencode auth list
opencode debug config | jq -r '.model, .default_agent, ((.provider // .providers // {})|keys)'
opencode debug config | jq -r '.permissions // .permission' | head -c 2000
```

Permission tests (manual, in a scratch repo):

- Ask the agent to read `~/.ssh/id_ed25519`; it must be denied.
- Ask it to run `git status; touch /tmp/pwned`; the shell rule must not treat
  the whole string as an allowed `git status`.
- Ask it to `curl https://example.com`; it must be denied/ask.
- With `--auto`, repeat the above inside the sandbox; verify the sandbox, not
  just the permission prompt.
