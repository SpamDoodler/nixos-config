# Route map template

Save as `research/ROUTES.md`. Keep it short; link to task cards, verdicts and
the decision log rather than restating them. Use stable route IDs (`R1`, `R2`,
…). Count a merged route as new only if it is admitted as a new approach.

```markdown
# Exploration routes

Problem:
Success / useful partial answer:
Assumptions and conventions:
Limits: active routes …; routes admitted …; new cards …; rounds …
Used: routes admitted …; new cards …; rounds completed …
Current round and in-flight ledger IDs:

| ID | Mechanism and assumptions | Discriminating test and stop/reopen rule | State | Ledger IDs and evidence |
| --- | --- | --- | --- | --- |
| R1 | … | … | active / parked / dropped / merged / handed off | … |

## Connections
- R… → R…: transferable result or obstruction; supporting IDs; compatibility status.

## Decisions
- Round …: what was learned; route changes and reasons; next test.

## Handoff or stop
- Verified evidence versus provisional ideas:
- Best next test and what it would resolve:
```
